# 核心算法原理与复杂度分析

[English](algorithm.md) · [返回首页](../README.zh-CN.md) · [训练指南](training.zh-CN.md) · [C/C++ 接口](c-api.zh-CN.md)

本文从零讲清楚：**硬路由 QKV-ROSA 的精确反事实梯度到底在算什么、为什么朴素做法慢到 $O(bT^4)$，以及当前引擎如何用「单次因果区间扫描」把它压到随机输入期望 $\widetilde{O}(T)$、一般最坏 $\widetilde{O}(T^2)$**。

---

## 1. 先把问题写清楚：硬路由前向与反事实信用

一条序列长度为 $T$，每个时间步的 $Q_t, K_t$ 都是打包好的 $b$ 位无符号整数（$1 \le b \le 64$），值向量 $V_t \in \{0,1\}^b$。

### 1.1 硬路由前向

在第 $t$ 步，只能回头看严格更早的历史键 $r < t$。记 $F_t(r)$ 为后缀 $Q[0..t]$ 与 $K[0..r]$ 的最长公共后缀长度：

$$
(L_t, e_t) = \max_{0 \le r < t} (F_t(r), r)
$$

按字典序取最大：**先比匹配长度 $L_t$，长度相同时选更晚的终点 $e_t$**。如果所有 $r < t$ 都连最后一个符号都对不上，记为空路由 $(0, -1)$。

路由决定输出载荷：
- 匹配成功（$e_t \ge 0$）：输出紧跟在终点**后面**的载荷 $P_{e_t + 1} = (2 V_{e_t + 1} - 1) \odot e_1$（注意 $r < t$ 保证 $r + 1 \le t$，仍严格满足因果性）。
- 匹配为空（$e_t = -1$）：输出可学习的空嵌入 $e_0$。

> **前向实现**（见 [`forward.h`](../qkv_rosa/csrc/forward.h) 和 [`causal_windows.h`](../qkv_rosa/csrc/causal_windows.h)）：采用增量后缀窗口索引 + 精确因果后缀自动机（SAM），带有界哈希探测与有序溢出保护，保证任意输入最坏 $O(T \log T)$ 时间、$O(T)$ 空间。

### 1.2 反向目标：单 bit 反事实信用

设上游传来的梯度为 $g_t = \partial L / \partial Y_t$。对于 $Q$、$K$ 或 $V$ 中的某一个具体 bit $i$，把它单独翻转并按上述规则重跑硬前向，得到新的输出 $Y^{\text{flip}(i)}$。该 bit 的**一阶反事实信用**定义为：

$$
C_i = \sum_{t=0}^{T-1} g_t^\top \big(Y_t^{\text{flip}(i)} - Y_t\big)
$$

二阶局部信任模式把线性内积替换为带对角惩罚的局部分数 $f_t(y) = g_t^\top(y - Y_t) + \frac{1}{2}\sum_j h_{t,j}(y_j - Y_{t,j})^2$。由于非空载荷的逐坐标平方恒为 $e_{1,j}^2$，实现中把载荷以第一个可达载荷 $P_1$ 为中心平移，并附加 1 维空路由指示通道，**直接把二次模型无损化归为同一套线性投影接口**（见 [`engine.h`](../qkv_rosa/csrc/engine/engine.h) 中的 `Features` 类）。

- **对于 $V$**：翻转 $V$ 不改变任何路由，只需沿原路由做一次线性散射即可在 $O(Tb)$ 时间内算完所有 $V$ 信用和 $e_0, e_1$ 梯度。
- **真正的难点在 $Q$ 和 $K$**：翻转 $Q$ 或 $K$ 的一个 bit 可能破坏已有匹配，也可能修好一个原本差 1 bit 的失配从而产生更长匹配。

## 2. 为什么朴素做法慢？以及如何一步步拆解

朴素做法对每个要翻转的 bit（共 $O(Tb)$ 个）重跑一次 $O(T^3)$ 的前向，总耗时 $O(bT^4)$。即使利用公共后缀 DP，逐个尝试「修改位置 × 输出行」也至少需要 $\Omega(bT^2)$ 甚至 $O(bT^3)$。

本引擎的突破来自两个直觉非常清晰的核心思想：
1. **先扔掉绝对不可能参与匹配的时间点**（因果坐标压缩）；
2. **把单次 bit 翻转拆成三个互不重叠的增量层次**，一次因果扫描直接算完所有有效修改。

---

## 3. 第一步：因果坐标压缩（去掉无效时间间隔）

如果时间步 $u$ 上的 $Q_u$ 与之前某位置 $s < u$ 上的 $K_s$ **完全相等，或者恰好只差 1 个可编辑 bit**，我们就在 $(u, s)$ 之间画一条因果边。

不难看出：任何合法的精确匹配、或单 bit 修复后的匹配，里面对齐的每一对符号都必然是一条因果边。因此，**既没有入边也没有出边的时间点，永远不可能成为任何精确匹配或单 bit 修复匹配的一部分**。

引擎在 [`edit_alphabet.h`](../qkv_rosa/csrc/engine/edit_alphabet.h) 中用两组互补的 bit 投影（高半段 / 低半段）做一次 $O(T)$ 扫描找出所有活跃时间点：
- 任何至多差 1 bit 的词对，在高半段和低半段中至少有一半完全一致；
- 轻桶（候选 $\le 8$）直接核验完整 64-bit 词，重桶保守标记所有更早的参与时间点，确保发现阶段对任意输入严格 $O(T)$；
- 把每段连续的无效时间点**收缩为单个分隔符**，同时在保留端点 $r'$ 上绑定原序列的真实载荷 $P_{r+1}$（即使 $r+1$ 本身被删掉了）。

**为什么压缩后结果完全等价？** 因为合法匹配绝不会跨过分隔符，且保留下来的符号相对先后顺序不变，所以匹配长度、修改归属位置和同长平局顺序全部严格保持不变。

当打包位宽较大时（如 $b=24, 32, 64$），独立随机序列中存在因果边的期望数量为：

$$
\mathbb{E}[E] = \binom{T}{2} \frac{b + 1}{2^b}
$$

例如 $T=8192, b=32$ 时，期望因果边数仅约 **0.258 条**——绝大多数位置会被瞬间压缩掉，实际进入核心归约的序列长度接近零！

---

## 4. 第二步：把一次翻转拆成三层望远镜求和

对于固定输出行 $t$（原路由 $B = (L, e)$）以及任意单个 $Q$ 或 $K$ 的 bit 翻转，定义三个路由最大值（均按「长度优先、终点次之」取最大）：

- **$S$（幸存路由 / Deletion）**：假设直接屏蔽被修改的位置，不准匹配跨过它，剩下最好的精确路由。
- **$U$（单符号修复）**：在 $S$ 和所有长度为 1 的单符号修复中取更优者。
- **$W$（完整赢家）**：在 $U$ 和所有长度 $\ge 2$ 的长修复中取更优者。

于是该次翻转在这一行的贡献可以写成严格恒等的三段望远镜分解（[`interval_credit.h`](../qkv_rosa/csrc/engine/interval_credit.h)）：

$$
f_t(W) - f_t(B) = \underbrace{\big[f_t(S) - f_t(B)\big]}_{\text{① 幸存项（删除）}} + \underbrace{\big[f_t(U) - f_t(S)\big]}_{\text{② 单符号修复增量}} + \underbrace{\big[f_t(W) - f_t(U)\big]}_{\text{③ 长匹配修复增量}}
$$

这三项各自有极其高效的处理方式：

### ① 幸存项（Deletion）：所有 bit 共用同一份删除账
屏蔽位置 $u$ 并不区分你翻的是它的第几个 bit，因此同一位置的所有 $b$ 个 bit **完全共用一份删除贡献**。
- **Q 侧删除**：屏蔽 $Q$ 中年龄为 $a < L$ 的位置 $t-a$，等价于把匹配长度上限压到 $a$，幸存终点就是长度 $\ge a$ 的最晚历史出现。
- **K 侧删除**：只有落在原获胜区间 $[e - L + 1, e]$ 内的 $K$ 位置才会破坏原匹配。
- **三种分级快速路径**（严格等价）：
  1. **单一连续段（Single-run）特判**：如果原匹配是一整段相同符号且历史上该符号只在这段连续区间 $[A, e]$ 出现，删掉内部 $s$ 后直接裂成左右两段，用差分数组 $O(1)$ 更新区间权重，最后一次扫描完成点积（全常数序列降至 $O(Tb)$）。
  2. **常规短行（$L \le \text{local\_limit}$）**：直接查当前扫描维护好的打包后缀倒排表（`Level`）。
  3. **超长行（$L > \text{local\_limit}$）**：统一收集，最后交给 [`delete.h`](../qkv_rosa/csrc/engine/delete.h) 中的周期等差数列（AP）删除原语批量处理，避免长匹配退化。

### ② 单符号修复增量：按符号类别一次性聚合
- **$Q_t$ 末位翻转**：直接查翻转后的符号在 $K[0..t-1]$ 中的最新出现位置即可，$O(1)$ 完成。
- **$K_s$ 翻转**：什么时候单符号修复能打败幸存路由？**当且仅当行 $t$ 原匹配长度 $L_t \le 1$ 且 $s$ 比 $Q_t$ 原本的最新精确出现位置更晚**（如果 $L_t \ge 2$，就算破坏了内部某个符号，原终点 $e$ 仍留下至少长度为 1 的后缀并在平局中胜出）。
- 因此，在倒序扫描 $s$ 时，只要按 $Q$ 的符号类别累加 $L_t \le 1$ 的行权重，一旦遇到该类别的下一个精确 $K$ 出现就清零重置——单次线性扫描就能算完所有 $K$ 的单符号修复！

### ③ 长匹配修复增量（长度 $\ge 2$）：打包后缀枢轴 + 二分搜索
对于长度 $\ge 2$ 的修复匹配，设末尾未修改的精确公共后缀长为 $a$，那么唯一的单 bit 失配一定落在 $(Q_{t-a}, K_{r-a})$，修复后总长度为：

$$
\text{len} = a + 1 + \operatorname{LCSuffix}(t - a - 1,\, r - a - 1)
$$

同一个候选同时服务于 $Q_{t-a}$ 和 $K_{r-a}$ 的对应 bit！

为了不枚举所有历史位置，引擎将 $K$ 的符号压缩成紧凑编号，并用 64 位整数滚动打包最近最多 $D$ 个符号作为前缀/后缀桶键（[`interval_credit.h`](../qkv_rosa/csrc/engine/interval_credit.h) 中的 `Level`）：
- 在第 $t$ 行选择查询深度 $p = \min(t, \max(2, \min(D, L+1)))$；
- 枚举把最近 $p$ 个符号中某一位替换成 1-bit 邻居后的打包词，直接查深度 $p$ 的精确倒排表，即可覆盖所有长度 $\ge p$ 的修复候选；
- 对于 $Q$ 侧长度小于 $p$ 的修复，因为「长度为 $h$ 的编辑后缀是否存在」关于 $h$ 单调，只需做一次倍增 + 二分查找就能定位最长/最新终点，无需遍历每一层倒排表；
- 对于 $K$ 侧长度小于 $p$ 的修复，只有两种可能赢：要么在长度 $L$ 处以更晚终点打平胜出，要么终点落在原获胜区间附近 $[e-L+1, e+p-1)$（且如果深度 $p$ 存在两个不相交精确出现，则可证明所有 $K$ 编辑都至少保留长度 $p$，直接跳过局部窗口检查！）。

## 5. 复杂度总结与证明要点

在固定打包位宽 $b$、数值维数 $d$ 和联合 bit 预算 $J$ 的前提下：

| 场景 | 时间复杂度 | 说明 |
|---|---|---|
| **独立均匀随机键 $K$ + 任意独立查询 $Q$** | **期望 $\widetilde{O}(T)$** | 见下方证明思路；$V$ 与上游梯度 $g$ 可任意取值 |
| **任意最坏输入（含极端周期/重复串）** | **$\widetilde{O}(T^2)$** | 受输出敏感量 $M + J_{\text{post}} + H$ 与长行删除原语控制 |
| **常数全相同序列** | **$O(Tb)$** | 触发单连续段差分快速路径 |

**为什么独立均匀输入下期望是 $\widetilde{O}(T)$？**
1. 令字符集大小 $\sigma = 2^b$，临界深度 $D_0 = \lceil \log_\sigma T \rceil$。当查询深度 $p \ge D_0$ 时，每一行命中半径为 1 的打包桶的期望端点数至多 $T(1 + bD_0)\sigma^{-D_0} = O(b \log T)$。
2. 当 $p < D_0$ 时，说明当前行没有长度为 $p$ 的精确匹配。把前 $t$ 个键切成互不相交的长度 $p$ 窗口，全部失配的概率按指数衰减 $\exp[-(\lfloor t/p \rfloor - 2)_+ \sigma^{-p}]$，与候选命中概率相乘并对所有位置求和，每层期望访问量仅 $O(p(1 + bp))$。
3. 由联合界（union bound），任意位置出现长度超过 $\lceil 3 \log_2 T \rceil$ 的原匹配的概率至多 $1/T$。因此长行删除原语只在概率 $\le 1/T$ 的极小事件上触发，即便按最坏 $\widetilde{O}(T^2)$ 计费，其期望贡献仍只有 $\widetilde{O}(T)$。

## 6. 精确性的三个层次

阅读代码或核对数值时，需要分清「精确」的三层含义：

1. **路由 100% 精确**：符号比较均核验完整 64-bit 键（含 bit 63 和 `UINT64_MAX`），因果边界与最长/最新平局规则零近似；`randomized=True` 开关的查询缓存同样比对完整键，绝不凭哈希值判断相等。
2. **代数项 100% 完整**：在默认 `backward_mode="exact"` 下，反事实信用公式的每一项都被完整计入，没有任何概率抽样或丢弃。
3. **浮点结合顺序**：C++ 内部使用 IEEE `float64`（编译禁用 FMA 收缩 `-ffp-contract=off`）。由于区间聚合改变了加法结合律顺序，输出与逐项朴素累加之间存在正常的浮点舍入差（实测相对 L2 误差 $< 10^{-14}$）。
