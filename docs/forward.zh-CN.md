# 一条更轻的精确因果前向

[English](forward.md) · [实现](../conv_rosa_transformer/csrc/forward.h)

## 前向究竟返回什么

`rosa_core.matching_stats(q, k)` 接受两列打包的 `uint64` 符号，返回 `(lengths, routes)`。
处理第 t 行时，枚举满足 `0 <= r < t` 的 K 终点，求以 `(t,r)` 结尾的最长相等后缀：

```math
L_t(r)=\max\{\ell\in\mathbb Z_{\ge0}:\ell\le\min(t,r)+1,\;
Q_{t-\ell+1:t+1}=K_{r-\ell+1:r+1}\},
```

切片左闭右开，允许长度为零。先选最长的匹配，同长时选最新终点。
空匹配统一为 `(0,-1)`，空输入返回两个空列表。例如 `Q=K=[0,1,0,1,0]`，
第 4 行返回 `(3,2)`：终点 4 虽然能匹配五个字符，却还不满足因果条件。
之后模型层再读取 `V[r+1]` 或空 embedding；这个路由接口不负责 payload。
索引建立在完整 K 上，适用于整段输入及 prefill；这里没有实现增量解码接口。

## 只有一条轨迹，为什么还需要倍增？

后缀自动机 SAM 把出现终点集合 `endpos` 相同的子串放进同一状态，各状态保存最早终点 `first`。
第 t 行的转移可用，当且仅当目标满足 `first < t`；否则沿 suffix link 缩短后缀，再尝试转移。
实际匹配长度始终落在当前状态代表的长度区间中。

因果边界会移动，但这不会破坏常见的摊还证明。把当前任意合法匹配
的最后一位删掉，它的终点变成 `r-1 < t-1`，所以前一行就已经合法。
因此新一行的最长匹配至多比上一行长 1。每次 suffix-link 回退至少
让长度减少 1，而长度不会为负。T 行总共最多回退 T 次，尝试转移
最多 2T 次。这条轨迹不需要排序 Q，也不需要反向计算的倍增表和出现链。

## 三个能直接证明最新终点的条件

转移成功后，设目标状态的终点集合为 E，`first=min(E)`、`last=max(E)`、
`count=|E|`。此时已经检查过 `first < t`，至少存在一个因果终点。

1. **最后一次出现已经可见。** 若 `last < t`，答案就是 `last`。
2. **区间中没有缺口。** 若 `count == last-first+1`，最小、最大终点之间
   的每个整数都在 E 中，因果最大值便是 `min(last,t-1)`。
3. **直接延伸达到了上界。** 若没有发生 suffix-link 回退，设上一行
   非空匹配的最新终点为 p。当前任何合法终点 r 的前驱都属于上一行的
   终点集合，故 `r <= p+1`。只要 `p+1 < t` 且 `K[p+1] == Q[t]`，
   这个上界就真的可达。回退会改变所匹配的后缀，所以回退后禁用此条件。

这些条件只回答端点查询，不修改匹配状态，也不绕过 `first < t`。
它们是对任意输入都成立的证明；三个条件都不满足，再做一般查询。

## 真正遇到难查的端点，再建树

在 suffix-link 树中，一个状态子树里的前缀 terminal，恰好对应它的全部出现终点。
DFS 排列后，它们占据一个连续区间；只为 T 个实际 terminal 留位置。

第一次有查询无法被证书解决时，把 `0,...,t-1` 这些终点放入各自位置，
再自底向上建立最大值线段树，共 O(T) 工作。后续先补上新出现的终点，再查目标状态的区间。
每个终点最多激活一次。如果证书能回答所有查询，最大值树始终不会分配，也不会做端点更新。

## 随机性只改变耗时，不改变答案

SAM 转移使用带进程级随机种子的平坦哈希表。查找时完整比较状态编号和符号的全部 64 位，
哈希值不充当相等判据。碰撞只会多探测几个位置，不会把不同符号误认为相同。
表容量至少为最大边数的两倍；同一符号跨回退复用哈希计算，状态的盐值也预先缓存。

这里没有证明通用哈希族的性质，坏碰撞仍可能让耗时退化。在平均探测代价为常数的假设下，
SAM 构造和匹配扫描为 O(T)，一般端点维护为 O(T log T)，整体是
**O(T log T) 时间、O(T) 辅助空间**，时间界带有上述哈希假设。
不能把完整前向写成无条件线性；证书成立时，对应的端点工作才可以省掉。

## 实测前向耗时

[原始报告](../benchmarks/results/forward.json) 保存了 21 组输入、全部计时
样本、输入哈希与动态库哈希。测量日期为 2026-10-25，机器是 Intel
Xeon Platinum 8573C，固定在逻辑 CPU 8，每组取七个样本，新旧交替计时。
原生口径包含 SAM 构造、实际建立的辅助索引以及全部路由查询；公开接口
还包含连续 NumPy `uint64` 输入的检查，以及两个输出转为 Python 列表。
两者都不计 payload 读取或聚合、神经网络投影、编译和首次调用预热。

| 输入 | T | 原生路由器（ms） | 公开 `matching_stats`（ms） |
|---|---:|---:|---:|
| 全相同 | 8,192 | 0.367 | 0.634 |
| 随机二进制 | 8,192 | 2.297 | 2.377 |
| 随机 16 符号字母表 | 8,192 | 1.893 | 2.162 |
| 随机 8 位符号 | 8,192 | 1.583 | 1.534 |
| 随机 64 位符号 | 8,192 | 0.475 | 0.788 |
| 周期串 | 8,192 | 0.596 | 0.833 |
| Shadow | 8,192 | 0.750 | 1.151 |
| 随机二进制 | 65,536 | 36.823 | 40.422 |
| 随机 64 位符号 | 65,536 | 6.220 | 8.069 |

64 位输入中，有四分之一的 Q 被设成前一个 K 符号，包含真实历史匹配。
周期串的周期为四，其中 K 改动一位；Shadow 为 `Q=0^T, K=10^(T-1)`。
两种口径独立计时，个别中位数的轻微倒置来自波动，不代表包装层有负开销。

### 与上一版前向的小对照

外部基线是上轮交付实现中的 `SamQRepairs(...,d=0)` 扫描，
不是原始上游反向算法。

| 输入 | T | 旧原生耗时（ms） | 当前原生耗时（ms） | 加速 |
|---|---:|---:|---:|---:|
| 随机二进制 | 65,536 | 59.915 | 36.823 | 1.63× |
| 随机 8 位符号 | 8,192 | 7.731 | 1.583 | 4.88× |
| 随机 64 位符号 | 8,192 | 5.374 | 0.475 | 11.31× |

全部输入的原生加速为 1.63–11.31×，公开接口为 1.48–9.26×。
这是这些输入的测量结果，不是对所有输入的统一保证。复现时运行
[forward.py](../benchmarks/forward.py)，传入
`--baseline-dir <previous-checkout> --cpu <available-core> --repeat 7`。
