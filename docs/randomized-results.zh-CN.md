# 随机化反向传播：实测结果与适用边界

[English](randomized-results.md) · [算法教程](randomized-backward.zh-CN.md) · [训练接口](native-training.zh-CN.md)

最终实现能在大量修复走廊共享数值计算时取得大幅加速，也有近似更慢、误差过大的输入。这份报告把它们一起列出。默认仍是**随机化搜索的精确反向传播**；近似反向需要显式开启。

## 设置与版本

| 本文名称 | 设置 | 含义 |
|---|---|---|
| 精确 | `backward_mode="exact", randomized=True` | 完整计算有限修改信用；随机化改变搜索工作量，不改变答案 |
| A0 | `backward_mode="approximate", approximation_rows=32, approximation_channels=0` | 抽样经过零证书筛选的行残差，或在成本规划器选中时使用全部频域通道 |
| A8 | A0 的基础上设置 `approximation_channels=8` | 再对频域通道抽样；需要额外显式开启 |

A0 的通道预算 0 表示**使用全部通道**，不是不做计算，也不会关闭行抽样。两种近似设置都不承诺任意输入的相对误差界或逐位一致。一阶、二阶使用同一接口。这里的“精确”指所选有限修改信用规则的精确结果；对角二阶规则是代理模型，不是任意外围神经网络的真实 Hessian。

**在线版**是 `b510fd9479946f10e46ced1a6265695cbc131d0a`。**P1** 是冻结的中间行抽样实现 `5e3e9f81965242492ae5a3870efd3cfbbca4bf9e`。当前精确、A0、A8 使用同一最终 native 二进制，SHA-256 为 `a732d50fd3f12342320f19306b6a5292b3d6aa829ff2c3a8b43d64e28dfc9cb5`。[清单](../research/results/randomized_final_manifest.json)记录证据和源码身份；旧实验会在后文单独注明。

## 计时到底包含什么

| 范围 | 包含内容 | 应当如何理解 |
|---|---|---|
| 信用计算核心 | 私有探针里的路由、信用计算 | 用于研发定位瓶颈，不等于完整反向或训练步加速 |
| native 反向 | 公开 NumPy/native 调用、校验和分配、metric 与提案、信用、联合修改重放、logit 映射、V/embedding 累加及 trace 返回 | 下方完整 26 组结果 |
| 普通训练步 | 清梯度、模型前向及投影、loss、反向、Adam | 后面的独立训练表 |

native 计时不含模型前向、loss、优化器和编译。数据是 Linux x86-64 上固定到逻辑 CPU 8、**九次交错运行的中位数**。训练固定在 CPU 2，OpenBLAS、OMP、MKL、Torch 线程数均明确设为 1；训练计时不含数据生成、评估、编译和诊断日志。这些都是 CPU 测量，没有据此推断 GPU 吞吐。

## 完整 native 反向结果

时间单位均为毫秒。误差是**拼接后的原始 Q/K logit 梯度**相对 L2 误差的中位数，以百分数表示。`≈0` 表示相对误差小于 `1e-10`，不代表逐位相等。所有案例中，当前精确模式的 Q/K/V/embedding 输出都与在线版**逐字节一致**；近似的 V、embedding 梯度也逐字节一致。选中的联合修改代码相同，联合代价通过记录的 `1e-12` 容差检查。全部计时样本、误差抽样见[原始 native 报告](../benchmarks/results/random_final_native.json)。

† 表示真实模型上游梯度：context 的 B×G 为 4×4，两种 prefix 均为 1×2。其余为 1×1，使用合成上游梯度。`wide` 是完整 64 位字并植入因果的一位邻居；`narrow` 用 64 位字存八位词表。`sparse_periodic` 只有最后一行的上游梯度非零。同一捕获状态分别代入一阶、二阶规则。

大收益集中在有相应结构的输入上。D8 prefix 捕获的二阶 A0 反向耗时 **12.432 ms**，在线版为 272.466 ms。D64 prefix 的 A0 为 **34.084 ms**，A8 为 **25.005 ms**，在线版为 304.820 ms。这里 A8 的原始 QK 误差为 0.811%，而 **Q 单独的误差为 3.341%**。

反例同样明确。随机 D8 在 32 行预算下，二阶原始 QK 误差达 229%；context 为 103%。一阶 periodic 的拼接误差为 247%，**Q 单独误差达 713%**，不能称为精确的梯度近似。随机 D16、narrow 二阶、all_same 上，A0 比当前精确实现更慢。当前精确模式本身也有退步：shadow D1 二阶耗时 509.272 ms，在线版为 439.798 ms。全表中，当前精确相对在线版加速为 0.864×–10.212×，A0 为 0.847×–52.422×；最大值不是普遍保证。

没有选中频域收缩时，A8 与 A0 使用相同的行估计器，这些行里的小幅计时差异不能归功于通道抽样。使用全部通道的 FFT 也改变了浮点计算顺序，本身不属于保证输出相同的精确随机化。

## 为什么不默认抽八个通道

另一个最终公开 API 实验固定 D64 prefix 捕获，每个配置抽样 16 次。`balanced` 保留原始上游梯度；`tangent` 去掉它沿当前输出的分量，使精确常数控制项变弱；`nine_tangent` 还将能量集中在九个通道。这是局部梯度诊断，不是训练曲线。表中测量真实 float32 累加后的共享投影参数梯度，以及传向前面网络的输入梯度。

| 上游梯度 / 阶数 | Q 参数误差 % | Q 余弦 | QK 参数误差 % | 输入梯度误差 % |
|---|---:|---:|---:|---:|
| balanced / first | 0.813 | 1.000 | 0.198 | 0.086 |
| balanced / second | 0.704 | 1.000 | 0.171 | 0.072 |
| tangent / first | 286.434 | 0.370 | 17.549 | 5.882 |
| tangent / second | 0.434 | 1.000 | 0.106 | 0.044 |
| nine_tangent / first | 55.740 | 0.871 | 3.323 | 0.996 |
| nine_tangent / second | 0.278 | 1.000 | 0.068 | 0.031 |

一阶 tangent 的问题很严重：Q 参数梯度误差 **286%**，余弦只有 **0.370**。把未变的 K 拼进来后，误差降到 17.5%、余弦升到 0.985，会掩盖 Q 的损伤。另一方面，balanced 二阶的共享 QK 参数误差为 0.171%，输入误差为 0.072%。决定通道预算时，两类结果都应考虑。

[完整 A8 控制实验](../research/results/training_round_final_channel_controls.json)还保留单个、九个通道占优的结果；V、embedding 逐字节相等，联合修改检查通过。[四组 A0 控制实验](../research/results/training_round_final_channel_controls_full.json)覆盖 balanced/tangent 与一阶/二阶，float32 参数和输入梯度误差均为 **0**。这支持频域路径默认保留全部通道，不代表另一个行抽样路径没有噪声。

## 最终运行时的普通训练

这个 prefix-copy 任务刻意保留长修复走廊：B1、G2、D64，Adam 学习率 0.003，每步重新生成数据。每次运行做 **20 个普通更新，每步一次模型前向、一次反向**。loss 定义为各行 `0.5 * sum(error**2)` 的平均，不是逐坐标均方误差。单元格依次列总训练步耗时（秒）与最终留出集 loss。1101 是探索时使用的 seed；2401、2402 未参与探索。

| T / 阶数 / seed | 初始 loss | 精确：秒 / loss | A0：秒 / loss | A8：秒 / loss |
|---|---:|---:|---:|---:|
| 2048 / second / 1101 | 27.06270 | 5.379 / 14.83426 | 0.830 / 14.75660 | 0.652 / 14.59788 |
| 2048 / second / 2401 | 27.94375 | 5.346 / 9.35802 | 0.867 / 9.35802 | 0.761 / 9.35389 |
| 2048 / second / 2402 | 27.22209 | 5.358 / 26.39198 | 0.793 / 26.39198 | 0.884 / 26.75267 |
| 2048 / first / 1101 | 27.06270 | 4.009 / 43.10059 | 0.903 / 43.51060 | 0.843 / 43.91100 |
| 4096 / second / 1101 | 27.07714 | 19.501 / 15.54690 | 未测 | 1.530 / 15.54690 |

T4096 时，A8 用时 **1.530 秒，精确版 19.501 秒，完整实测训练步加速 12.74×**。这一组的 20 次 batch loss、硬前向哈希全部与精确版相同，最终留出集 loss 也相同；但 Q/K 参数从第一个更新起就已不同。这个长度只测了精确与 A8，没有测 A0。这是 20 步的结构压力实验，不能据此认定普遍收敛或任意模型都能获得相同加速。

T2048、探索 seed 1101 的 A8 完整训练步加速为 8.25×。P1 也重跑了一次：0.830 秒，最终 loss 13.77414；它使用自己的冻结旧二进制。整个套件包含 15 次运行、300 个更新，其中含这一次 P1 对照。

两处失败必须保留。新的二阶 seed 2402 上，A8 **比 A0 更慢，留出集 loss 也略差**，各方法的学习进展都很有限。没有为一阶重新调参的配置中，三种方法都把 loss 从 27.06 提高到 43–44；执行快并不等于学得好。

## 旧训练证据仍然属于旧版本

冻结的 P1 实验做了 59 次运行、17,916 个更新。三个新 seed 的上下文召回中，精确与 row32 都达到 100% 的非空 payload 准确率，但密集检索出现了精确基线也学不会的 seed；加权周期复制中，残差被证书消去，各参数轨迹相同，但近似并未稳定获得速度收益。再加可训练的残差 tanh MLP 前置网络后，精确与 row32 都失败；明确标注为后续隔离对照的去前置网络实验让精确基线恢复了学习。因此，任意深层模型的稳定训练仍未验证。

中间的索引行实现还与 P1 做了 **600 个配对上下文更新**：参数更新、硬前向全相同。它匹配的是 P1，不是精确规则，而且早于最终冻结的运行时。由于第一个精确运行期间校验、计数代码发生改变，汇总标为 `SOURCE_CHANGED`；不能把其计时说成最终冻结性能。清单会标出这些历史报告；完整文件和淘汰的实验保留在研究包中，包括 `research/training_round_frozen_results.md`、`research/results/training_round_phase2b_context.json`。

## 复现与使用

[native 基准脚本](../benchmarks/random_final_native.py)使用记录的在线版、P1 检出及研究包里的捕获输入，重跑全部五种方法。原始报告含九次计时、逐次误差、工作量计数、源码哈希、加载库哈希和源码未变检查。安装方法与不变的 `loss.backward(); optimizer.step()` 训练循环见[训练指南](native-training.zh-CN.md)。

先使用默认精确模式。若选择近似，设置 `backward_mode="approximate", approximation_rows=32, approximation_channels=0`，同时检查 Q 单独、QK 拼接误差与真实任务的 loss 曲线。正通道预算（如 8）是额外且显式的取舍。[算法教程](randomized-backward.zh-CN.md)给出了估计器期望正确的推导，也解释了为什么无偏本身不能保证误差小、优化轨迹好。
