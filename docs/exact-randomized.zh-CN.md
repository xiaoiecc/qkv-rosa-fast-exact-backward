# 精确随机化：缓存重复工作，答案保持不变

[English](exact-randomized.md) · [算法推导](../ALGORITHM.zh-CN.md) · [近似反向](randomized-backward.zh-CN.md) · [实测](subquadratic-results.zh-CN.md)

`randomized=True` 在同一套后缀索引算法中启用有界缓存。它不采样 bit 修改、匹配候选、输出行或数值通道；命中必须比较完整查询键，未命中就执行原来的精确查询。固定输入、信用规则和其余随机种子，开关这一选项的完整反向输出逐 bit 相同。

```python
from conv_rosa_transformer.rosa_layer import NBitQKVRosa

cached = NBitQKVRosa(128, 8, randomized=True)   # 默认
uncached = NBitQKVRosa(128, 8, randomized=False)
```

比较时要复制相同参数，并固定前向及联合提案的种子。这个布尔值只控制查询加速，不改变训练规则，也不关闭独立的联合 bit 提案。

## 1. 缓存的是哪一个问题

令 $F_t(r)$ 表示 Q 第 $t$ 行在 K 终点 $r$ 的精确后缀匹配长度。反复出现的索引查询是

```math
R(t,h,c)=\max\{r<c:F_t(r)\ge h\},
```

没有结果则返回 $-1$，因果上界裁成 $c\le t$。后缀排名区间找到长度-$h$ 的 Q 后缀，再由波列矩阵前驱查询选出最晚合法 K 出现。删除、区间投影和修复裁剪可能多次问到同一个问题。

长度为一、不可能的长度，以及最近终点已匹配等证书，都先于缓存探测。只有真正需要后缀区间查询时才创建缓存。因此，直接证书已经解决的流不付缓存分配和哈希费用。

每项保存完整 `(t, h, c, result)`。带种子的整数混合函数把三个查询整数映射到一个槽位；容量是 $2n$ 到 $4n$ 之间的二次幂，因此内存和替换操作都有明确上限。

## 2. 哈希冲突为什么不会弄错路由

| 查找结果 | 执行操作 |
|---|---|
| 槽位里的完整键与查询相同 | 返回保存的精确终点 |
| 槽位为空 | 执行后缀索引查询，写入结果 |
| 槽位被另一个键占用 | 执行后缀索引查询，替换该槽位 |

哈希只决定放在哪里，不证明两个查询或符号相等。即使所有查询都挤进一个槽，答案仍然正确，只是命中率会很差。打包符号本身通过完整值离散化和精确后缀/LCP 结构比较。

一元控制和相邻二元组证书的完整字典也限制探测链长度：至多探测 16 次，之后退到保存完整键的有序映射；后缀符号查找使用有界探测和有序二分。因此恶意碰撞除了不会弄错答案，也不能把字典查找拖成线性扫描。[碰撞测试](../tests/cpp/bounded_hash.cpp)会主动构造这些溢出情形。

缓存也不改变数值运算顺序：它用已保存的整数终点，替代重新算一遍相同的整数终点；调用方随后执行的浮点操作完全一样。因此这里的开关逐 bit 相等有明确依据。

## 3. 复用率低时，不一直付探测费

很少重复的工作可能被缓存拖慢。实现每观察 512 次探测，若命中不足 32 次，就跳过接下来的 2,048 次缓存探测，直接查询，再重新观察一段。不同阶段的复用情况可能不同，所以绕过不是永久关闭。

这些数值是实现常数，不是精度参数。绕过缓存从不丢掉贡献。策略限制无效探测，但仍不保证每种输入都更快：哈希、键比较和额外内存访问可能比省下的查询更贵。应同时报告完整耗时与命中、未命中计数。

代码在 [index.h](../conv_rosa_transformer/csrc/subquadratic/index.h)。一个索引属于一个流，它的可变缓存不供多个调用同时访问；不同 batch/group 流各自持有索引。

## 4. 种子与复现

原生选项区分 `proposal_seed` 和 `repair_seed`：前者用于有限预算联合 bit 提案，后者用于查询缓存布局，并在显式近似时参与采样盐值。适配器随前向状态冻结这些选项。切换 `randomized` 不改变该次前向的提案种子或框架 RNG 消耗。

没有联合提案的一阶完整模式，不需要为这个缓存多抽一次 Torch 随机数。关闭缓存后，二阶模式仍会保留其本来的联合提案随机性；关闭查询加速不等于关闭训练规则。近似模式的采样由独立、显式的选择控制，见[近似反向](randomized-backward.zh-CN.md)。

固定种子支持在同一实现与数值环境内复现。这里保证的是其余输入、随机选择都固定时的缓存开关比较，不是不同采样种子、编译器或浮点环境下训练轨迹相同。

## 5. 精确搜索与浮点完整计算要分开理解

当前完整引擎会批量聚合区间，并在适合时使用 FFT。路由精确，也不遗漏数学信用项，但 binary64 分组和 FFT 可以与历史直接累加产生不同舍入；开关缓存都遵守同一个约定。

`backward_mode="approximate"` 才是允许统计估计的另一个选项。它在相关路由最大值确定以后，采样完整残差行，或显式选择的数值通道。单独设置 `randomized=True` 不启用这些估计器。
