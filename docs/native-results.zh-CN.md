# 原生训练与精确随机化：结果、范围和负例

[English](native-results.md) · [接入与推导](native-training.zh-CN.md) · [随机化证明](exact-randomized.zh-CN.md)

本轮固定两项实现：批量 C++ 训练，以及不丢任何根邻居的随机分块查询。
训练规则沿用上一轮选定的直径定标对角信任项与一个独立联合位块；仍可切回
原一阶。`randomized` 只改变搜索过程，不降低信用计算精度。默认 `False`，
因为一些小输入及直接查询回退行没有可靠的收益。

## 先分清三种计时

| 口径 | 计入 | 不计入 |
|---|---|---|
| 信用核心 | 每次全部索引、Q/K/V 信用、路由、数值累计；复用输入输出缓冲 | Python 检查、logit 映射、联合提案、投影、优化器 |
| 硬组件 | 打包、前向、对角项、提案、单点信用、联合重放、logit 与 embedding 梯度、适配器转换 | Q/K/V/O 稠密投影、下游模型、优化器 |
| 完整层 | 硬组件及 Q/K/V/O 稠密投影与其梯度 | 下游模型、loss、优化器 |

运行环境是 Intel Xeon Platinum 8573C、GCC 13.3、Linux、PyTorch 2.14.1+cpu、
NumPy 2.3.5。计时使用一个固定 CPU 核与一个 Torch 线程；编译、预热在计时外。
随机化核心每行 11 次交替测量，组件每行 7 次。表格是中位数；前向、反向和
它们之和各自取中位数，因此中位数不保证可以相加。原始样本的离散程度较大，
下面的小比值不能自动解释成算法收益。

本轮比较的上一轮研究基线为 `f6d7c4b73d7040b1b33860f5a2649c3cd3036cc5`。
它不是在线仓库提交；下载交付包保留了该基线。PR 应用基准另为在线 `4248b46`。
原始在线仓库的旧测量仍单独保存在 benchmarks 中，不与本轮拼成同一次实验。

## 2. 随机化究竟省掉了什么

宽位宽时，以前要为每个不同 Q 词逐位查根字典。现在按随机位块查询覆盖桶，
完整 XOR 核验后仍返回全部一位邻居；大桶改做精确逐位查询。根表也改成稀疏
掩码加 CSR，两侧开关共用这一表示。

最清楚的一行是 T=8192、D=64 的植入一位修复输入：524,288 次完整根查询，
变为 16,384 次桶查询和 2,048 次成员核验。SAM 准备由 7.960 ms 降到
1.713 ms，完整信用核心由本轮 off 的 20.094 ms 降到 on 的 12.033 ms，
**单独开启随机化为 1.670×**。相比 f6 的 21.824 ms 则为 1.814×。

该行只存 2,048 个根目标；原来的逻辑密表有 524,288 项。这是目标项数，
不是分配器峰值或 RSS。vector 仍会预留容量，完整梯度输出仍有 O(TD) 个数。

所有 15 行都保留如下；`wide` 含植入的一位修复，`narrow` 只变化低八位，
输入标签仅属于生成器。所有输入运行同一套核心。

## 3. 为什么这轮没有选择更激进的梯度抽样

把信用拆为共同删除项 B 与修复残差 R 后，可以无偏抽整条 bit 通道。
本轮进一步给它一个实际算法拿不到的优势：事先知道全部残差能量，求给定预算
下最优的重要性概率。即便如此，半预算时随机 D8 的相对 RMS 误差仍为 84.7%，
随机 D16 为 70.3%，宽 D64 为 97.2%。想把该固定输入的误差压到 10% 以内，
前两者必须保留全部 8/8、16/16 通道，宽 D64 也要至少 63/64。

这否定的是这些输入上靠整通道稀疏化获得低噪声大收益的希望，不是随机算法的
一般下界。精确分块查询把随机性用在发现过程，故无需用训练误差交换这些收益。
完整推导与原始能量在 [随机化指南](exact-randomized.zh-CN.md) 和
[noise_ceiling.json](../research/results/native_random_noise_ceiling.json)。

## 4. 普通训练：开关等价，但旧实现迁移有负例

用了两个实际组合模型任务：固定样本的 MSE 检索，以及每步换样本的交叉熵检索。
新种子 901、902、903，各 100 步；包含前后投影、任务头、loss、Adam 更新。
每步只有一次模型前向和一次 `backward`。本轮没有为迁移结果另调超参数。

| 任务，3 seed 均值 | f6 | 当前二阶 off | 当前二阶 on |
|---|---:|---:|---:|
| MSE 训练 loss | 0.068074 | 0.009362 | 0.009362 |
| MSE 测试 loss | **0.278856** | **0.528012** | **0.528012** |
| MSE 100 步耗时 | 5.902 s | 0.360 s | 0.331 s |
| Fresh CE 训练 loss | 0.000641 | 0.000879 | 0.000879 |
| Fresh CE 测试 loss | 0.000558 | 0.000788 | 0.000788 |
| Fresh CE 100 步耗时 | 5.415 s | 0.312 s | 0.310 s |

当前 off/on 的六组成对运行中，每一步参数、loss 轨迹及最终框架 RNG 都逐位
一致。另用两种信用模式、两种规模及下游 Dropout 检查了输出、梯度、权重和
RNG，仍逐位一致。小 toy 的 17 倍左右加速主要来自去掉大量 Python batch/group
循环；D4 输入的根规划器会回退，不能把它宣传成随机化得到 17 倍。

**迁移后的 MSE 测试损失变差了。** 更小的训练 loss 没有转化为更好的泛化。
Fresh CE 两者准确率均为 100%，但当前交叉熵数值也略差。三种子只能说明这些
有限实验；既不能据此宣布新数值实现必然更差，也不能用计算精度掩盖负例。

### 第一次分叉追到了哪里

对测试损失最差的 seed903，从相同权重和 RNG 开始逐步追踪：初始前向完全
相同，联合提案身份完全相同，联合角点成本差至多 6.94e-18，所有参数的梯度
最大绝对差为 1.49e-8。

问题发生在近零梯度。一个 emb0 坐标的旧/新梯度为 −2.794e-9 / −9.313e-10。
Adam 的 epsilon 为 1e-8、学习率为 0.03，第一步更新便分别约为 0.006551 /
0.002556，参数差达到 0.003996。完成 5 次更新后、下一次前向时（第 6 次更新前），
31 个 Q bit 首次分歧：
旧 logits 恰好为 0，新 logits 为约 7.44e-14 或 1.49e-13。阈值使用 `z > 0`，
所以硬 bit 不同。在此之前，提案身份和框架 RNG 一直一致。

旧单点 logit 映射和部分归约在 Torch float32 中进行；原生实现使用 binary64
中间值后再转回 tensor dtype。上述记录说明：小的浮点变化能够被 Adam 的近零
更新和硬阈值放大。它不是随机化遗漏了候选，也不能保证旧训练轨迹逐位复现。
当活动行数超过提案行预算时，旧 NumPy PCG64 与新 mt19937_64 的固定 seed
采样轨迹也不同；这个追踪例子中没有发生该类提案差异。

## 5. 正确性与未覆盖的范围

[原生验证记录](../research/results/native_cpp_validation.json) 中共运行 88 个测试，87 个通过，
1 个 CUDA 测试跳过，包含独立暴力、结构 oracle、原生/冻结规则的单步容差检查、
实际双位障碍、优化器、checkpoint、GradScaler 与 state_dict 合同。
后补的四块规划器和 sampled/forced 通道轨迹测试也单独通过；这些计数有重叠。
生产源码在所有正式计时及验证期间冻结。完整 C++ 可脱离 Python/Torch 编译。

本轮是 CPU 结果，没有 GPU 原生内核。对角项是选择的局部信任模型，不是真实
下游 Hessian；二阶更新依赖传入 g，不保证对不同 loss 的梯度可加，也不支持
二次 autograd。普通单次 backward 使用方式无需修改优化器。较长真实模型的
泛化、峰值 RSS 和分布式吞吐仍未测量。上述限制不改变随机根查询不漏候选的
证明，但限制了可以从这些实验推广出的训练结论。
