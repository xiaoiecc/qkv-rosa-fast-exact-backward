# Correctness tests

Run from the repository root with Python, NumPy, PyTorch and a C++17 compiler:

```bash
python tests/run.py --output build/validation.json
python tests/run.py --exhaustive --output build/validation_exhaustive.json
```

The runner discovers all `test_*.py` files, records the loaded implementation's
source hashes, and fails if those sources change during the run. GCC/Clang are
supported, including WSL; select the compiler with `CXX`. CPU tests do not verify
native CUDA performance. A CUDA integration test can be skipped when no CUDA
runtime is available. Test counts from nested or historical reports overlap;
use the report generated by the particular command instead of adding counts.

## Exact and approximate randomized backward

For the focused public-interface and structural checks:

```bash
python -m unittest tests.test_randomized_join tests.test_native_approximation tests.test_spectral_training tests.test_approx_row_certificate tests.test_approx_row_credit
```

| Tests | Contract checked |
|---|---|
| `test_randomized_join` | Complete neighbor search, including direct/two-block/four-block plans and full-word verification |
| `test_native_approximation` | Both credit orders, preserved forward/V/embedding behavior, exact joint corners, independent random streams, ordinary optimizer integration |
| `test_spectral_training` | Long-corridor contraction, exact-zero recovery, sparse support, explicit channel budgets, repeatable seeds, external-cache bounds |
| `test_approx_row_certificate`, `test_approx_row_credit` | Independently enumerated zero certificates and complete selected-row credits |

The default `backward_mode="exact", randomized=True` changes search work while
preserving the complete numerical result. Approximation is explicit:
`backward_mode="approximate"`. Its default channel budget of zero means all
spectral channels; a positive budget permits additional channel sampling.
Approximate tests use stated numerical tolerances where the evaluation order
changes. They do not establish a universal relative-error bound or prove that
training loss will decrease.

`research/approx_round_binding.py` and `research/approx_round_certificate.py`
are small test bindings to C++ headers. Frozen Python snapshots and the existing
`joint_bits.py` / `causal_candidates.py` compatibility imports are test oracles,
not alternate production backends. Production imports no research module.

## Independent definitions and floating-point contracts

`oracle.py` directly tries each causal endpoint, compares suffix characters,
applies longest-then-latest selection, flips each Q/K/V bit and reruns the hard
forward. It does not reuse production deletion/repair logic. Integer cases
require exact equality; ordinary floating cases state their absolute/relative
tolerances; routes always require exact equality.

The default independent binary enumeration has 341 Q/K inputs. `--exhaustive`
extends it to 5,461 and enables three standalone C++ structural oracles for
deletion/interval contraction, causal occurrence/latest endpoints, and repair
continuations. The numerical tests distinguish constant-output zero credits,
saved integer cancellation witnesses, and exact dyadic expansion against
Python `Fraction`. The latter requires round-to-nearest, gradual underflow,
no intermediate overflow and no fast-math transformations.

Native framework checks additionally cover first/second order, logit mappings,
empty inputs, bit 63, selected joint corners, the two-bit zero-signal barrier,
checkpointing, GradScaler, strict weight restoration and RNG isolation. Native
exact randomization off/on is checked bitwise; migration comparisons against
the frozen Python arithmetic use explicit tolerances.

## Performance and learning are separate checks

The [final manifest](../research/results/randomized_final_manifest.json) links
validation and measured artifacts. The [results report](../docs/randomized-results.md)
keeps every native case, large approximation errors, slowdowns and failed toy
training runs. [Reproduction instructions](../research/README.md) distinguish
credit-core probes, complete native backward and whole training steps.

The PR retains the final runtime and its tests. Larger experiments, historical
runtime snapshots and rejected helpers are in the separate study archive.
Passing these tests does not replace the retained learning failures or imply
arbitrary deep-model stability.
